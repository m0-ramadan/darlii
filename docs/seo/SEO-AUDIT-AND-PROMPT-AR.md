## التعديلات

1. تحويل GET وHEAD من www إلى https://darlii.com بكود 301 مع الاحتفاظ بالمسار والاستعلام. طلبات POST لا يعاد توجيهها بهذه القاعدة حفاظًا على بيانات النماذج.
2. توحيد أصل توليد URLs عند إعداد APP_URL بأحد نطاقَي الإنتاج إلى https://darlii.com، دون تعديل .env. يشمل توليد الخريطة من CLI وrobots وcanonical وروابط الأصول.
3. منع عرض تفاصيل مقالات ووظائف غير منشورة، وصفحات وكلاء غير نشطين، واستبعاد العقارات غير المنشورة من عقارات صفحة الوكيل.
4. عدم اختلاق lastmod جديد للرئيسية عند غياب تاريخ محتوى فعلي.
5. إضافة اختبارات للتحويل والاحتفاظ بالاستعلام وتمرير الطلبات الأخرى.

## المطلوب داخل Search Console

1. استخدام Domain property إن أمكن، أو التأكد أن الخاصية المطابقة هي https://darlii.com/.
2. إرسال https://darlii.com/sitemap.xml بعد التأكد أن كل loc بدون www وأن الخريطة تعود 200.
3. فحص الرئيسية والعقارات وعقار ومقال ووكيل عبر URL Inspection > Test live URL. راجع حالة السماح بالفهرسة وGoogle-selected canonical وUser-declared canonical.
4. طلب فهرسة عدد محدود من الصفحات الأساسية بعد نجاح الاختبار الحي. لا تكرر الطلبات لنفس الرابط ظنًا أنها تسرع الزحف.
5. تصدير عنوانَي 404 من تقرير Pages. الرابط المحذوف نهائيًا بلا بديل يبقى 404/410 ويزال من الروابط والخريطة؛ الرابط المنقول فقط يحول 301 لبديله المكافئ. لا تحول كل 404 للرئيسية.
6. مراجعة Crawl stats وHost status وSecurity issues وManual actions؛ نقل النتائج الفعلية قبل استنتاج وجود مشكلة استضافة أو عقوبة.
7. مراقبة تطور عدد الصفحات المفهرسة ووقت الزحف بعد التغييرات. لا تضغط Validate fix لمجرد اختفاء مشكلة في الكود قبل التحقق من عناوين التقرير.

## برومبت شامل قابل للنسخ

أنت مهندس Laravel وخبير SEO تقني ومحتوى. استكمل تدقيق موقع https://darlii.com من المشروع الحالي، ونفّذ الإصلاحات المثبتة مع الحفاظ على التصميم والوظائف والبيانات. اقرأ AGENTS.md والتقرير docs/seo/SEO-AUDIT-AND-PROMPT-AR.md والجدولين قبل العمل، وابدأ من آخر نتيجة مؤكدة. لا تكرر إصلاحات موجودة ولا تفترض أن Discovered - currently not indexed يعني حظرًا في robots أو خطأ 404.

المخرجات المطلوبة: أدلة لكل مشكلة، أولويتها وتأثيرها، التعديلات الدقيقة، اختبارات مناسبة، مقارنة قبل/بعد لكل URL، تقرير بما بقي مع السبب، وخطوات Search Console التي تتطلب وصولًا للحساب. لا تعد بفهرسة أو ترتيب مضمونين. لا تستخدم بيانات أو أسعارًا أو تقييمات أو مراجعات أو عناوين شركات مختلقة.

نفّذ التدقيق التالي:

### الزحف والنطاق والاستجابات
- اجمع كل روابط sitemap وتقارير Search Console وروابط HTML الداخلية، واتبع ترقيم العقارات والمدونة والوكلاء والمشروعات حتى النهاية بحدود طلبات منخفضة.
- افحص النسخ HTTP/HTTPS وwww/بدون www والشرطة النهائية و/ar و/en والروابط القديمة واختلاف حالة الأحرف والـslugs العربية والمرمزة.
- سجّل السلسلة الكاملة للتحويلات، واكشف الحلقات والتحويلات المتسلسلة و5xx و403 و429 وsoft 404 والصفحات التي تفتح بمحتوى غير مناسب.
- تحقق من CDN/WAF مع طلبات desktop/mobile ومقارنة المحتوى دون ادعاء أن تغيير User-Agent يثبت إمكانية وصول Googlebot الحقيقي.
- راجع timeouts وDNS وTLS وسجلات الزحف إن توفرت، وتحقق من هوية Googlebot عند تحليل السجلات.

### robots وsitemap وcanonical واللغات
- تأكد أن robots متاح وأن CSS وJS والصور الضرورية غير محجوبة وأن Sitemap يشير للدومين المختار.
- افحص meta robots وX-Robots-Tag على المحتوى العام وصفحات الدخول والإدارة والبحث والفلاتر والمفضلة والأخطاء والمحتوى غير المنشور.
- لا تمنع URL في robots إذا كان المطلوب أن يزوره Google ليقرأ noindex.
- تأكد أن الخريطة تحتوي فقط الروابط الأساسية العامة الصالحة وأن تحديثها ذري، وlastmod يعكس تعديل المحتوى الحقيقي والترجمات، دون تحديث زائف كل عشر دقائق.
- تحقق أن canonical واحد مطلق صحيح ولا يعتمد على مضيف عشوائي، وأن صفحات الترقيم لها canonical مناسب لا يرجعها جميعًا للصفحة الأولى.
- راجع hreflang على الصفحات ذات الترجمات الحقيقية فقط، مع روابط متبادلة وإشارة ذاتية، ولا تعلن لغة إنجليزية لصفحة عربية أو URL يتحول لصفحة مختلفة.

### قابلية اكتشاف كل صفحة
- ابنِ خريطة روابط من عناصر a[href] الفعلية، وحدد عمق الوصول من الرئيسية والصفحات اليتيمة بعد زحف الترقيم كاملًا.
- اختبر الترقيم مع JavaScript معطلًا، وحالات الصفحة الأولى والأخيرة والخارج عن النطاق؛ امنع فراغ صفحات 200 غير المفيدة.
- راجع breadcrumb وروابط العقارات المشابهة ومقالات ذات صلة وروابط الوكلاء والمواقع الجغرافية والمشروعات، وأضف روابط مفيدة فقط.
- تعامل مع الفلاتر والبحث والترتيب والتتبع وفق سياسة واضحة تمنع تضخم URLs دون إخفاء صفحات بحث جغرافية مفيدة فعلًا.

### المحتوى والنية المحلية
- افحص title وdescription وH1 لكل صفحة، والتكرار الفعلي وتشابه النصوص ووضوح نوع العقار والموقع والسعر والمساحة وحالة التوفر.
- راجع المقالات التجريبية والعامة والترجمات الآلية وصفحات الوكلاء قليلة المعلومات؛ اقترح تحسينات محددة، ولا تحذف أو تعيد كتابة محتوى تجاري واسع بلا أساس.
- راجع المقالات بناء على السوق المصري وبني سويف، وصحة المعلومات واسم الكاتب وتاريخ التحديث ومصادر الادعاءات.
- تحقق من NAP: الاسم والعنوان والهاتف وساعات العمل ووسائل الاتصال، واتساقها مع البيانات الفعلية. لا تخترع فرعًا أو موقعًا جغرافيًا.
- افصل صفحات العقارات المتشابهة بمعلومات حقيقية، وراجع العقارات المباعة والمكررة وأكواد المرجع وتحويلات تغيير slug.
- افحص العناوين والصور والنص البديل واللغة وRTL في الموبايل، ولا تجعل التغييرات الشكلية بديلًا عن محتوى مفيد.

### البيانات المنظمة
- افحص JSON-LD فعليًا: Organization/RealEstateAgent وWebSite وBreadcrumbList وArticle وRealEstateListing وJobPosting حيث تنطبق.
- تحقق من @id والروابط والصور والتواريخ والأسعار والعملة والعنوان والحقول المطلوبة والتطابق مع المحتوى المرئي.
- لا تضف AggregateRating أو Review غير حقيقي، ولا تعتبر نجاح schema.org ضمانًا لميزة Rich Result.
- راجع تاريخ انتهاء الوظائف وإزالة JobPosting عند إغلاقها وسياسة صفحات الوظائف المنتهية.

### الأداء والعرض
- قِس PageSpeed للموبايل والكمبيوتر، وفرق بين بيانات Lighthouse المعملية وCrUX الحقيقية. افحص LCP وINP وCLS وTTFB.
- حلل حجم HTML الكبير لقائمة العقارات، والاستعلامات المتكررة وN+1 وإعادة بناء الهيدر والفوتر والمحتوى المكرر والطلبات الخارجية.
- افحص صور LCP وsrcset والأبعاد وlazy loading والصيغ الحديثة وخطوط العربية وCSS/JS التي تعطل العرض.
- لا تفعل cache عام يعرض بيانات مستخدم أو CSRF أو المفضلة أو عملة زائر لغيره. تحقق من الضغط وCache-Control وCDN وفق حساسية كل استجابة.
- اختبر تحميل كل الصور الأساسية؛ وجود onerror يخفي الصورة المكسورة للمستخدم لكنه لا يصلح المصدر أو صورة og:image.

### الاختبارات والإطلاق
- أضف اختبارات سلوكية للمشاكل الفعلية: canonical والتحويلات والترقيم والمحتوى غير المنشور والخريطة والـ404، باستخدام قاعدة اختبارات معزولة فقط.
- شغّل الاختبارات باستخدام PHP 8.3+؛ إذا تعذر ذلك صرّح بالسبب ولا تدّع نجاحها.
- لا تشغل migrations أو أوامر Git مدمرة، ولا تغير .env أو بيانات الإنتاج. التزم بسياسة النشر المصرح بها في AGENTS.md وتحقق حيًا بعده.
- اختم بجدول مشكلة/دليل/إصلاح/تحقق/متبقٍ. افصل ما تم إثباته من توقعات التحسن وما يحتاج بيانات Search Console أو قرار محتوى.
